# 재현 가능한 판정 추적 예시

아래 예시는 특정 외부 평가 자료나 실제 설문 원자료가 아닙니다. 저장소의 모의 데이터와 명백한 합성 문자열만 사용해 `입력 → 근거 → 관문 → 출력 → 사람의 판정`을 추적하는 방법을 보여 줍니다. 라이브 API 키나 외부 네트워크는 필요하지 않습니다.

## 예시 1: 일부 식별정보 패턴 마스킹

입력은 합성 문자열입니다.

```text
연락은 hong@example.com, 010-1234-5678, 사번 A-1234입니다.
```

재현 명령:

```powershell
python -c "from survey_insight.preprocessing import mask_pii; print(mask_pii('연락은 hong@example.com, 010-1234-5678, 사번 A-1234입니다.'))"
```

현재 결과:

```text
('연락은 [EMAIL], [PHONE], [EMPLOYEE_ID]입니다.', ['email', 'phone', 'employee_id'])
```

판정 근거는 이메일·국내 이동전화·사번 접두 패턴과의 일치입니다. 이 예시가 이름, 주소, 희귀 사건 서술까지 탐지한다는 뜻은 아닙니다. 담당자는 보고서 배포 전에 남은 식별 가능 정보를 별도로 검토해야 합니다.

## 예시 2: 감정 신호와 처리 우선도

입력은 합성 문자열입니다.

```text
만족하지만 업무가 과중하고 즉시 개선이 필요합니다.
```

재현 명령:

```powershell
python -c "from survey_insight.sentiment import analyze_text_sentiment; print(analyze_text_sentiment('만족하지만 업무가 과중하고 즉시 개선이 필요합니다.'))"
```

현재 근거 어휘는 `만족(+0.75)`, `과중(-0.50)`, `개선(-0.35)`, `필요(-0.35)`와 우선 표현 `즉시(0.90)`입니다. 극성은 `(0.75 - 1.20) / 1.95 = -0.231`, 양·음 근거가 함께 있으므로 라벨은 `mixed`입니다. 우선도는 중복 없는 근거 가중치를 `1 - product(1 - weight)`로 결합해 `0.955`입니다.

현재 출력의 핵심 필드:

```text
polarity_label='mixed'
polarity_score=-0.231
urgency_score=0.955
evidence_terms=('만족', '과중', '즉시', '개선', '필요')
source='rule_lexicon_fallback'
```

관문은 점수 범위와 근거 어휘의 실제 존재입니다. 이 값은 심리 상태나 실제 긴급성을 판정하지 않으며, 사람이 먼저 읽을 후보를 정렬하는 신호입니다.

## 예시 3: 샘플 토픽 후보에서 권장안 선정

저장소의 `sample_data/mock_survey_responses.csv`는 80개의 모의 응답입니다. 현재 의존성 범위와 seed 42에서 다음 명령으로 전체 후보와 보고서를 다시 만들 수 있습니다.

```powershell
$env:SURVEY_INSIGHT_DISABLE_NETWORK='1'
python -m survey_insight.cli analyze `
  --input .\sample_data\mock_survey_responses.csv `
  --out .\out_evaluation `
  --seed 42
```

2026-08-09 로컬 점검 환경에서 허용 범위는 4–10개였고, 구조 관문을 통과한 NMF 5개 토픽 후보가 권장됐습니다. 해당 후보의 기록값은 다음과 같습니다.

| 항목 | 값 |
|---|---:|
| 복합 평가값 | 0.582 |
| 군집 분리도 | 0.015 |
| 토픽 해석 가능성 점수 | 0.548 |
| 분석 포함률 | 1.000 |
| 토픽 키워드 다양성 | 1.000 |
| 라벨 해석 가능성 | 1.000 |
| 토픽 크기 균형 | 0.904 |
| 페널티 | 0.000 |
| 가중치 시나리오 선정률 | 0.957 |
| 가중치 선정률 Monte Carlo 표준오차 | 0.009 |
| 가중치 시나리오 점수 10–90백분위 | 0.512–0.664 |
| Bootstrap 구조 관문 통과율 | 0.850 |
| Bootstrap 최소 토픽 비율 2.5백분위 | 0.026 |
| 부분표본 일치도 평균 | 0.243 |
| 부분표본 일치도 10–90백분위 | 0.146–0.370 |

판정 순서는 다음과 같습니다.

1. 후보 토픽 수가 허용 범위 안인지 확인합니다.
2. 빈 토픽이 없고, 모든 토픽이 소표본 정책의 최소 크기를 만족하며, 분석 포함률이 70% 이상인지 구조 관문으로 확인합니다.
3. 관문 통과 후보에서 `0.30×군집 분리도 + 0.25×토픽 해석 가능성 + 0.15×분석 포함률 + 0.10×키워드 다양성 + 0.10×라벨 해석 가능성 + 0.10×크기 균형 - 페널티`를 비교합니다.
4. 기본 가중치를 각각 50–150% 범위에서 바꾼 512개 시나리오에서 후보별 선정률을 계산합니다. 최고점의 5% 또는 0.03 이내 후보는 선정률을 먼저 비교하고, 같으면 더 단순한 토픽 수를 우선합니다.
5. 선택된 배정을 고정한 500회 bootstrap에서 토픽 비율 구간과 구조 관문 통과율을 확인하고, 별도로 5회 80% 층화 부분표본 재적합 ARI를 확인합니다.
6. 평가자는 `analysis_package.json`의 후보표·키워드·대표 응답을 읽고 5개 토픽이 실제 업무 질문에 적합한지 승인, 병합, 분할 또는 재라벨링합니다.

이 실행에서 가중치 시나리오 선정률은 `0.957`로 제한된 가중치 범위에서는 NMF 5개 후보가 자주 선택됐습니다. 반면 부분표본 재적합 ARI 평균은 `0.243`으로 현재 경고 기준 `0.60`보다 낮았습니다. 두 결과는 모순이 아닙니다. 전자는 **평가 가중치 변화에 대한 선택 강건성**, 후자는 **문서 일부가 달라졌을 때 분할이 다시 만들어지는 정도**를 봅니다. 따라서 이 샘플에서는 5개 토픽을 안정적인 정답으로 승인해서는 안 되며, 4개 등 더 단순한 후보와 대표 응답을 함께 비교하고 사람이 최종 구조를 정해야 합니다. Bootstrap 구조 관문 통과율 `0.850`과 가장 작은 토픽 비율의 2.5백분위 `0.026`도 작은 토픽의 표본 민감도를 보여 줍니다.

이 실행 결과는 정확도나 보편적인 최적 토픽 수의 증거가 아닙니다. scikit-learn 또는 Kiwi 버전, 전처리 결과, 입력 데이터가 달라지면 수치가 달라질 수 있습니다. 실행 날짜·환경·seed와 사람이 내린 최종 판단을 함께 보관해야 합니다.
