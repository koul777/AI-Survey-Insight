# 책임 있는 AI 운영 점검표

이 점검표는 AI Survey Insight를 공공기관·기업 HR 환경에서 사용하기 전에 사람이 확인할 최소 통제 항목입니다. 법률 자문, 개인정보 영향평가, 보안 인증 또는 공정성 인증을 대신하지 않습니다. 각 분석 run마다 담당자, 점검일, 데이터셋 ID, run ID, seed, 외부 provider 사용 여부와 근거 문서를 함께 기록하세요.

판정은 `통과`, `보류`, `해당 없음` 중 하나로 기록합니다. `보류`가 하나라도 있는 결과는 배포하지 않는 것을 기본 관문으로 삼고, 예외 승인자와 사유를 별도로 남깁니다.

| 영역 | 확인 질문 | 최소 증거 | 보류 조건 |
|---|---|---|---|
| 적법성·목적 제한 | 설문 수집 목적과 이번 분석·보고서 배포 목적이 일치하는가? 직원 평가·징계의 자동 근거로 사용하지 않는가? | 수집 고지, 처리 근거, 목적·수신자 기록 | 목적·처리 근거 또는 책임자가 불명확함 |
| 개인정보·보존 | 원본과 마스킹 후 텍스트를 담당자가 검토했는가? 보존기간과 삭제 책임자가 정해졌는가? | 마스킹 표본 점검, DB·보고서 경로, 삭제 기록 | 직접 식별자·희귀 서술이 남았거나 삭제 계획이 없음 |
| 외부 전송 | 외부 AI 사용 시 전송되는 마스킹 텍스트·대표 응답, 국외 이전, provider 보존 정책을 승인했는가? | provider·모델·전송 항목·승인 기록 | 승인 없이 외부 provider를 사용함 |
| 보안 | API 키를 요청 중에만 사용하고 로그·DB·package·보고서에 남기지 않았는가? 저장 장치와 접근 권한이 적절한가? | 자동 테스트, 접근 권한, 로그 표본 | credential 노출 또는 과도한 접근 권한이 확인됨 |
| 공정성·대표성 | 누가 응답하지 않았는지, 소집단·희귀 집단 결과가 왜곡되거나 재식별되지 않는지 검토했는가? | 응답률·누락 분석, 그룹별 표본 수, 억제 확인 | 작은 집단을 단정적으로 비교하거나 불이익 판단에 사용함 |
| 방법론 타당성 | 권장 토픽 수, 라벨, 대표 응답, 감정 신호의 반례를 사람이 검토했는가? | 후보표, 수정 이력, 반례와 검토 의견 | 휴리스틱 점수를 정확도·최적값·심리 진단으로 해석함 |
| 인간 감독 | 최종 보고서와 조치 제안을 승인할 업무 책임자가 지정됐는가? 자동 결과를 수정·기각할 수 있는가? | 검토자·승인자·수정 이력 | 자동 결과만으로 조치하거나 책임자가 없음 |
| 설명·이의제기 | 영향을 받는 사람이 분석 목적, 데이터 사용, 한계와 문의·정정·이의제기 경로를 알 수 있는가? | 안내문, 담당 창구, 처리 기한 | 문의·정정·이의제기 경로가 없음 |

## 배포 직전 관문

다음 항목을 모두 확인한 뒤에만 보고서를 공유합니다.

- [ ] 원본·마스킹 결과와 희귀 서술을 사람이 표본 점검했다.
- [ ] 권장 토픽 수와 자동 라벨을 담당자가 승인하거나 수정했고 변경 이유를 기록했다.
- [ ] 감정 신호와 처리 우선도를 긴급성·위험도·개인 심리 판단으로 사용하지 않았다.
- [ ] 5건 미만 표시 억제만으로 익명성이 보장된다고 주장하지 않았다.
- [ ] 외부 AI 전송이 있었다면 provider, 모델명, 전송 범위와 조직 승인을 기록했다.
- [ ] 수신자·보존기간·삭제 책임자와 이의제기 창구가 정해졌다.
- [ ] 검증되지 않은 정확도·공정성·보안성·완전 익명화 주장을 제거했다.

조직별 법률·노무·보안 요구는 서로 다르므로 실제 운영 전 해당 부서의 검토를 추가해야 합니다.
