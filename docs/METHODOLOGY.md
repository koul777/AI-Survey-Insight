# 분석 방법론

이 문서는 AI Survey Insight 0.2.1의 **현재 코드가 실제로 수행하는 계산**을 설명합니다. 이 도구의 결과는 탐색적 HR 분석을 돕는 후보안이며, 정답 라벨·통계적 유의성·심리 상태·개인의 위험도를 판정하지 않습니다. 내부 JSON 필드는 하위 호환성을 위해 유지될 수 있으므로, 사용자 표시 명칭과 내부 필드명이 다른 경우 아래 대응표를 기준으로 해석합니다.

## 1. 처리 단위와 재현성

- 입력은 CSV 또는 XLSX의 행이며, 사용자가 선택하거나 자동 추천된 한 컬럼을 자유응답으로 분석합니다.
- 로컬 후보 모델의 기본 난수 시드는 `42`입니다. CLI의 `--seed` 또는 API 요청의 `seed`로 바꿀 수 있습니다.
- 같은 라이브러리 버전·운영체제·입력·전처리·시드를 사용하면 로컬 후보 선택과 핵심 결과가 재현되도록 구성합니다. 라이브러리 버전, 부동소수점 구현 또는 외부 provider 응답이 달라지면 결과도 달라질 수 있습니다.
- 생성되는 `candidate_id`, `run_id`, `document_id`는 실행마다 새로 만들어지므로 재현성 비교 대상이 아닙니다.

## 2. 자유응답 컬럼 탐지

각 컬럼에 대해 헤더 의미, 문자열 길이, 자연어 형태, 고유값 비율, 문장형 표현을 계산합니다.

```text
text_score =
  0.25 × header_semantic
  + 0.25 × length_signal
  + 0.20 × value_type_signal
  + 0.15 × cardinality_signal
  + 0.10 × sentence_signal
  + 0.05 × model_vote
```

결측률이 95%를 넘으면 점수에 `0.65`를 곱합니다. `text_score >= 0.50`인 컬럼을 후보로 제시하고, `0.70` 이상은 `Free-text Response`, `0.50–0.70`은 `Free-text Candidate`로 표시합니다. 이는 지도학습 정확도가 검증된 분류기가 아니라 규칙 기반 프로파일러입니다. 헤더나 응답 형식이 특이한 데이터에서는 사용자가 컬럼을 직접 확인해야 합니다.

## 3. 전처리와 개인정보 패턴 마스킹

1. Unicode NFKC, 제로폭 문자, 공백과 줄바꿈을 정규화합니다. 빈 값·NaN·`없음`·`의견 없음`·`N/A`와 끝의 문장부호 변형을 무응답으로 제외합니다.
2. 이메일, 국내 이동전화, 명시된 사번/직번 패턴을 `[EMAIL]`, `[PHONE]`, `[EMPLOYEE_ID]`로 마스킹합니다. 명시적인 이름·주소·주민등록번호·계좌 문맥은 `privacy_review_flags`로 별도 표시합니다. 이 처리는 완전한 익명화를 보장하지 않습니다.
3. Kiwi의 전체 품사열을 공유합니다. 토픽은 일반명사·고유명사·영문·어근 등을 사용하고 감정은 형용사·동사·부정어·어미를 보존합니다. 유용한 한 글자 명사(앱·돈 등)는 유지하며 URL·마스킹 표식·일반적인 요청/감정 단어는 토픽 어휘에서 제외합니다.

   `split_complex=True`로 문맥에 따라 `복잡하/VA`와 `복잡/XR + 하/XSA`가 달라지는 문제를 정규화합니다. 사전 기본형의 마지막 `다`가 EC/EF 중 어느 태그여도 어간으로 비교합니다. 지원 범위는 Kiwi 0.23.2 이상, 0.25 미만이며 라이브러리와 사전 모델 버전을 함께 기록합니다.
4. Kiwi가 없으면 토픽은 Okt 또는 정규식으로, 감정은 표면형 사전 규칙으로 대체합니다. 대체 경로와 재검토 필요 상태를 기록합니다.
5. 주제 단어가 없는 응답은 토픽 미배정으로 남기고 감정분석에는 포함합니다. 문자 조각을 이용해 토픽을 만들어내지 않습니다.
6. 같은 마스킹 문장은 한 번만 모델에 적합합니다. 평가·재표본 진단도 중복 제거 문장 기준입니다. 결과의 토픽 건수·감정 분포·그룹 비교는 모든 원래 응답의 빈도를 복원합니다. `analysis_diagnostics`와 후보 `params`에서 두 단위를 확인할 수 있습니다.

카카오톡 입력은 시스템 알림·봇·명시적 반응을 분리하고 시간 간격과 메시지 수·문자 수 한도로 대화 구간을 만듭니다. 길이가 짧다는 이유만으로 `불편해요`, `임금체불` 같은 의견을 제거하지 않습니다. NFKC로 변환된 웃음·울음 자모도 반응으로 인식하며, 시간이 역행하면 새 구간을 시작합니다. `source_row_indices`는 헤더를 제외한 원본 데이터 행의 1부터 시작하는 번호입니다. 구버전 결과에 이 정보가 없으면 추정하지 않고 미기록으로 표시합니다.

토픽·감정 건수의 단위는 맥락 구간이며 사람 수나 개별 발화 수가 아닙니다. 구간은 여러 주제·발화자·상반된 감정을 담을 수 있습니다. 여러 사람을 한 그룹 구성원으로 세지 않도록 대화의 그룹 교차표는 생성하지 않습니다. `sentiment_summary.analysis_unit`과 `source_message_count`에 단위를 기록합니다.

## 4. 표현 공간

| 용도 | 표현 | 현재 설정 |
|---|---|---|
| KMeans·계층 군집·NMF | TF-IDF | 형태소 1–2그램, `min_df=1`, `max_df=1.0`, `sublinear_tf=True`, 최대 12,000 특성 |
| LDA | 정수 단어 빈도 | 같은 어휘 규칙의 CountVectorizer; TF-IDF를 LDA 입력으로 사용하지 않음 |
| 로컬 DBSCAN | TF-IDF → SVD → 정규화 | 최대 10성분, cosine 거리 |
| 선택 의미 군집 | 로컬 E5 또는 provider 임베딩 | KMeans·계층·DBSCAN 후보와 BERTopic 입력 |
| 하드 군집 키워드 | c-TF-IDF | TF-IDF 값이 아닌 실제 단어 빈도를 군집별 집계 |
| 후보 간 분리도 비교 | 하나의 공통 공간 | 임베딩을 사용하면 모든 후보를 해당 임베딩으로 평가; 없으면 TF-IDF |

로컬 의미 모델은 `intfloat/multilingual-e5-small`입니다. 명시적인 `setup-local-model` 명령만 모델을 다운로드하고 revision을 저장합니다. 분석은 로컬 파일만 읽습니다. E5의 clustering용 `query: ` 접두어와 정규화 임베딩을 사용합니다. 480 모델 토큰보다 긴 문서는 모든 구간을 따로 인코딩하고 토큰 수 가중 평균 후 정규화합니다. 모델 최대 시퀀스는 512토큰입니다. 구간 평균은 긴 글의 순서·세밀한 관계를 완전히 보존하지 않습니다.

설치되지 않았거나 추론에 실패하면 명시적인 경고와 함께 형태소 토픽모델만 사용합니다. 사용자가 외부 provider를 선택하면 마스킹된 문장이 외부 임베딩 요청으로 전송될 수 있습니다.

## 5. 토픽 후보 모델

중복 제거 후 주제 단어가 있는 문장 수 N에 따라 허용 토픽 수와 최소 토픽 크기를 먼저 제한한 뒤 후보를 만듭니다.

| 유효 응답 수 | 모드 | 허용 토픽 수 | 최소 토픽 크기 |
|---:|---|---:|---:|
| 0–14 | 초소표본 모드 | 1–3 | 2 |
| 15–29 | 소표본 모드 | 1–4 | 2 |
| 30–49 | 소형 설문 모드 | 1–6 | `max(3, ceil(0.08N))` |
| 50–199 | 표준 모드 | 1–10 | `max(4, ceil(0.04N))` |
| 200–999 | 대형 설문 모드 | 1–20 | `max(5, ceil(0.02N))` |
| 1,000 이상 | 대량 분석 모드 | 1–30 | `max(10, ceil(0.01N))` |

최대 토픽 수는 고유 토큰열 수와 `N // 최소 토픽 크기`를 넘지 않습니다. 5,000문장 초과에서는 작은 토픽 수를 포함한 최대 8개 토픽 수를 비교하며 MiniBatch KMeans와 MiniBatch NMF를 사용합니다. 이때 LDA·KL-NMF·DBSCAN·계층 후보는 생략합니다.

- **KMeans**: TF-IDF 또는 선택적 embedding에서 고정 `k` 후보를 생성합니다. 수렴 경고가 발생하거나 요청한 수보다 실제 군집 수가 적게 만들어진 붕괴 후보는 버립니다.
- **계층 군집**: 평균 연결과 cosine 거리를 사용합니다. TF-IDF와 embedding 모두 응답 250건 이하에서만 실행해 밀집 행렬 메모리 사용을 제한합니다.
- **Frobenius NMF**: TF-IDF의 비음수 행렬을 Frobenius 손실로 분해합니다. 문서–토픽 가중치의 최댓값으로 주 토픽을 정하고, **NMF 성분 자체**에서 상위 단어를 뽑습니다.
- **KL-NMF**: 같은 TF-IDF 행렬에 multiplicative update와 일반화 Kullback–Leibler 손실을 적용한 별도 후보입니다. scikit-learn의 토픽 추출 예제와 같이 희소성 정규화를 함께 사용합니다. 두 NMF 모두 최대 반복 횟수 안에 수렴하지 않거나 실제 토픽 수가 붕괴하면 경쟁표에서 제외합니다.
- **LDA**: 정수 단어 빈도 행렬을 batch 방식으로 적합합니다. 문서별 사후 토픽 분포의 최댓값으로 주 토픽을 정하고, **LDA 토픽–단어 성분 자체**에서 상위 단어를 뽑습니다. LDA는 [Blei, Ng, Jordan (2003)](https://www.jmlr.org/papers/v3/blei03a.html)의 생성 확률 모델 계열이지만, 이 제품은 짧은 설문 응답에 맞춘 탐색 도구이지 논문의 가정을 검증하는 도구는 아닙니다.
- **DBSCAN**: 정해진 `k` 대신 밀도에서 자연 군집 수를 얻습니다. 로컬 TF-IDF 후보는 `eps=0.35–0.75`, embedding 후보는 `eps=0.15–0.35`의 제한된 격자를 비교합니다. `-1`은 노이즈 응답으로 남깁니다.
- **선택적 embedding**: 사용자가 설치한 로컬 모델을 켜거나 provider와 키를 제공하면 의미 벡터 후보를 추가합니다. provider 호출이 실패하거나 Claude처럼 별도 embedding 경로가 없는 설정이면 로컬 후보만 사용합니다.

scikit-learn도 토픽 추출 예제에서 [Frobenius NMF와 일반화 KL-NMF에는 TF-IDF, LDA에는 단어 빈도](https://scikit-learn.org/stable/auto_examples/applications/plot_topics_extraction_with_nmf_lda.html)를 비교합니다. 본 구현은 이 입력 구분과 두 NMF 목적함수 구분을 따릅니다. 한 엔진이 특정 `k`에서 붕괴하더라도 다른 엔진은 독립적으로 계속 평가합니다.

### 5.1 토픽 키워드 표현

- KMeans·계층 군집·DBSCAN 및 embedding 군집은 각 군집을 하나의 class document로 보고 class-based TF-IDF를 계산합니다. 원 응답별로 토큰을 센 뒤 군집별로 합치므로 서로 다른 응답 사이에서 가짜 bigram을 만들지 않습니다.
- 일반 군집의 c-TF-IDF는 [BERTopic의 표현 방법](https://arxiv.org/abs/2203.05794)을 적용한 후처리입니다. 이와 별도로 카카오톡 입력은 실제 BERTopic 라이브러리의 UMAP·HDBSCAN 후보를 만듭니다. 로컬/외부 임베딩이 없으면 LSA 벡터를 사용하므로 이 경로에는 BERT 의미 임베딩이 없습니다.
- NMF·LDA는 잠재 성분 가중치를 그대로 키워드 점수로 사용합니다.
- 모든 엔진은 상위 후보에서 `캠페인`과 `캠페인 성과`처럼 한쪽 토큰 집합이 다른 쪽에 포함되는 1–2그램을 함께 표시하지 않습니다.
- 키워드 표현 단계는 군집 배정이나 문서–토픽 가중치를 변경하지 않습니다. 읽기 쉬운 라벨 근거를 만드는 후처리이며, 사람이 대표 응답과 함께 검토해야 합니다.

## 6. 구조 관문

후보 점수를 비교하기 전에 다음 조건을 별도 관문으로 검사합니다.

1. 유효 토픽이 한 개 이상이어야 합니다.
2. 각 토픽은 해당 표본 모드의 최소 토픽 크기 이상이어야 합니다.
3. DBSCAN처럼 노이즈를 허용하는 후보도 전체 유효 응답의 70% 이상을 토픽에 포함해야 합니다.
4. 고정 `k` 모델은 실제로 `k`개 군집이 생성되어야 합니다.
5. LDA는 절반 이상의 응답이 서로 다른 유효 단어 3개 미만이면 입력 근거 부족으로 관문을 통과하지 못합니다.

하나 이상의 후보가 관문을 통과하면 통과 후보만 권장안 경쟁에 참여합니다. 모두 실패하면 차선 후보를 표시하고 경고를 남깁니다. 70%는 보편적 통계 기준이 아니라 과도한 제외를 막기 위한 제품 정책값입니다.

## 7. 평가 지표와 실제 계산 의미

모든 값은 같은 입력 코퍼스 안의 후보를 정렬하기 위한 휴리스틱입니다. 서로 다른 조사·언어·전처리 결과 사이의 절대 품질 또는 정확도로 비교하면 안 됩니다.

| 사용자 표시 명칭 | 내부 필드 | 현재 계산 |
|---|---|---|
| 군집 품질 종합점수 | `stability` | 분리도 0.40 + 해석 가능성 0.30 + 균형 0.20 + 0.10 − 소형 토픽 비율×0.20. 과거 필드명을 유지한 복합 휴리스틱이며 통계적 안정성 검정이 아님 |
| 토픽 해석 가능성 점수 | `coherence` | 상위 5개 키워드의 문서 동시출현으로 계산한 bounded UMass-style 값 |
| 군집 분리도 | `semantic_quality` | 노이즈를 제외한 cosine silhouette. 음수는 0으로 제한 |
| 분석 포함률 | `coverage` | `-1` 노이즈가 아닌 응답 수 / 유효 응답 수 |
| 토픽 키워드 다양성 | `diversity` | 단어·구 포함 중복을 억제한 뒤 토픽별 상위 5개 키워드 중 고유 키워드 비율 |
| 라벨 해석 가능성 | `labelability` | 표현 완성도 50% + 키워드 응답 설명률 50%. 완성도는 키워드 존재량 60%·대표 응답 존재량 40%; 설명률은 상위 5개 키워드 중 최소 2개(하나뿐이면 1개)를 포함한 소속 문서 비율의 토픽별 평균 |
| 토픽 크기 균형 | `balance` | 토픽 크기의 정규화 엔트로피에서 65% 초과 최대 점유율을 감점 |
| 가중치 시나리오 선정률 | `weight_acceptability` | 구조 관문을 통과한 후보를 대상으로 기본 가중치 각각을 50–150% 범위에서 변동·재정규화한 512개 시나리오 중 해당 후보가 선택된 비율. 정확도 확률이 아님 |
| Bootstrap 구조 관문 통과율 | `bootstrap_gate_pass_rate` | 선정된 배정에 조건부로 응답을 500회 복원추출했을 때 모든 토픽이 최소 크기이고 분석 포함률이 70% 이상인 비율. 모델을 다시 적합하는 검정이 아님 |
| 부분표본 일치도 | `resampling_stability` | 선정 후보에 한해 토픽별 80% 층화 부분표본을 5회 다시 적합하고 원 분할과의 Adjusted Rand Index를 평균한 사후 진단값. 권장 점수에는 미포함 |

토픽 해석 가능성 점수는 각 토픽의 순서 있는 키워드 쌍에 대해 아래 값을 평균하고 지수화해 0–1로 제한합니다.

```text
raw_pair = log(min(1, (D(w_i, w_j) + 1) / max(1, D(w_j))))
coherence = exp(mean(raw_pair))
```

0.2.1의 `coherence_smoothed`는 별도 보조 진단입니다. `exp(mean(log((D(w_i,w_j)+0.5)/(D(w_j)+1))))`로 계산해 각각 한 번 나타난 비동시출현 단어쌍이 기존 평활에서 1.0을 받는 현상을 드러냅니다. 원 UMass 정의의 재현값이나 사람 평가 확률이 아니며, 복합 선정 점수에는 넣지 않습니다. 두 점수의 차이와 실제 응답을 함께 검토하세요. 현재 계산 프로파일은 `heuristic_v6_scale_invariant_diagnostics`입니다.

이는 [Röder et al. (2015)](https://doi.org/10.1145/2684822.2685324)이 정리한 coherence 계열을 참고한 **제품용 bounded UMass-style 변형**입니다. 논문의 모든 구성·외부 참조 코퍼스·사람 평가를 재현한 구현은 아닙니다. 군집 분리도는 [silhouette 계열](https://doi.org/10.1016/0377-0427(87)90125-7)을 사용하지만, 고차원 희소 텍스트에서 높은 값이 곧 의미적으로 좋은 토픽을 보장하지 않습니다.

## 8. 권장 토픽 수 판정

관문을 통과한 후보의 복합 평가값은 다음과 같습니다.

```text
score =
  0.30 × 군집 분리도
  + 0.25 × 토픽 해석 가능성 점수
  + 0.15 × 분석 포함률
  + 0.10 × 토픽 키워드 다양성
  + 0.10 × 라벨 해석 가능성
  + 0.10 × 토픽 크기 균형
  − penalty
```

`penalty`는 최소 크기 미달 토픽 비율, 응답 수 대비 과도한 파편화, 75%를 넘는 단일 토픽 점유, 노이즈 비율, 중복 키워드를 결합하며 최대 `0.35`입니다. 최고점과 `max(0.01, 최고점의 1%)` 이내인 후보가 여러 개면 가중치 시나리오 선정률이 높은 후보를 먼저 선택하고, 선정률도 같으면 더 단순한 작은 토픽 수를 권장합니다. 더 넓은 대안과 더 세분화한 대안도 별도로 제공합니다.

이 가중치와 임계값은 공개 benchmark로 최적화된 값이 아니라 설명 가능성과 운영상 검토 가능성을 위한 제품 정책입니다. 따라서 화면과 보고서에서는 “최적 토픽 수”가 아니라 **권장 토픽 수**라고 표시합니다.

### 8.1 가중치 민감도

고정 가중치가 유일하게 옳다는 가정을 피하기 위해 [SMAA](https://doi.org/10.1016/S0377-2217(97)00163-X)의 가중치 공간 탐색 아이디어를 제한적으로 차용합니다. 각 기본 가중치에 고정 seed의 `Uniform(0.50, 1.50)` 승수를 곱하고 합이 1이 되도록 재정규화한 512개 시나리오를 만듭니다. 각 시나리오에서 같은 구조 관문·근접 최고점·단순성 규칙을 적용해 후보별 선정 횟수를 집계합니다.

이 값은 학습된 “동적 최적 가중치”가 아닙니다. 50–150% 범위와 512회는 공개된 제품 정책이며 외부 정답이나 전문가 선호로 추정한 값이 아닙니다. 따라서 `weight_acceptability=0.80`은 “정답일 확률 80%”가 아니라 **선언한 가중치 변동 범위 안에서 80%의 시나리오가 같은 후보를 지지했다**는 뜻입니다. `weight_acceptability_mcse`에는 유한한 512회 Monte Carlo 표본 때문에 생기는 선정률 표준오차를 기록하며, 이는 모델 오차나 모집단 표준오차가 아닙니다. 선정률이 0.50 미만이면 다른 후보도 함께 비교하라는 경고를 냅니다.

### 8.2 재표본 진단

권장 후보가 정해진 뒤 중복 제거 문장 기준으로 두 종류의 재표본 진단을 수행합니다. 가중치 시나리오의 근접 점수 범위는 `max(0.005, 최고 점수의 1%)`입니다.

1. **Assignment-conditional bootstrap**: 현재 선택된 문서–토픽 배정을 고정하고 문서를 500회 복원추출합니다. 토픽별 비율의 2.5·97.5 백분위, 분석 포함률 백분위, 최소 토픽 비율 백분위와 구조 관문 통과율을 계산합니다. 이는 [Efron의 비모수 bootstrap](https://doi.org/10.1214/aos/1176344552) 원리를 사용하지만 모델을 다시 적합하지 않으므로 **현재 배정에 조건부인 표본 구성 변동성**만 보여줍니다. 모집단 신뢰구간, 토픽 진실성 또는 인과적 불확실성으로 해석하면 안 됩니다.
2. **층화 부분표본 재적합**: 각 토픽에서 80%를 비복원 추출한 부분표본을 고정 seed로 5회 다시 적합합니다. 원래 분할과 부분표본 분할을 라벨 번호 순열에 영향을 받지 않는 [Adjusted Rand Index](https://doi.org/10.1007/BF01908075)로 비교하고 평균과 10·90 백분위를 기록합니다. 평균이 0.60 미만이면 경고하지만 권장 점수를 사후 변경하지 않습니다. DBSCAN 권장 후보는 현재 이 진단을 지원하지 않습니다.

재표본에 의한 군집 안정성은 의미 없는 구조에서도 높을 수 있고, 안정성만으로 좋은 토픽을 보장하지 않습니다. 군집별 bootstrap 안정성을 별도로 보아야 한다는 [Hennig (2007)](https://doi.org/10.1016/j.csda.2006.11.025)과 토픽 수를 데이터 교란에 대한 용어 중심 안정성으로 비교한 [Greene et al. (2014)](https://arxiv.org/abs/1404.4606)을 참고하되, 현재 구현은 두 논문의 전체 알고리즘을 재현하지 않습니다.

### 8.3 통계적 검정력에 대한 범위

이 파이프라인은 명시적 귀무가설, 효과크기, 유의수준, 정답 토픽 또는 사전 표본설계를 사용하지 않으므로 고전적 의미의 **통계적 검정력(power)**을 계산하지 않습니다. 표본 수만으로 토픽 발견 검정력을 만들어내지 않으며, 소표본 모드·최소 토픽 크기·bootstrap 구간·부분표본 ARI는 모두 근거 강도와 민감도를 점검하는 진단입니다. 검정력이 필요한 연구에서는 분석 전에 검정할 가설과 결과변수, 최소 탐지 효과, 표집 구조를 별도로 정의하고 독립 검증 설계를 사용해야 합니다.

## 9. 대표 의견과 토픽 소속도

- 하드 군집은 중심 벡터와 cosine 유사도가 높은 중복 없는 응답을 최대 3개 선택합니다. 응답별 소속도는 음수를 0으로 제한한 토픽 중심 유사도의 상대 비율입니다.
- NMF·LDA는 해당 토픽의 문서 가중치가 큰 응답을 최대 3개 선택하고 전체 토픽 가중치 합이 1이 되도록 정규화합니다.
- NMF의 성분 H를 행별 L1 정규화하고 같은 배율을 W에 곱해 W·H를 보존합니다. 따라서 같은 분해의 임의 배율 차이가 소속도와 배정을 바꾸지 않습니다. 가중치가 모두 0인 문서는 이상치로 남깁니다. MiniBatch NMF의 부분표본이 5,000개 아래가 되어도 재적합에서는 원래 MiniBatch 알고리즘을 유지합니다.
- `membership_scores`에 토픽별 값을, `score_method`에 계산 방법을 기록합니다. 하위 호환 필드 `probability`는 배정 토픽의 소속도이며 보정된 분류 정확도 확률이 아닙니다. LDA의 모델상 사후 가중치와 NMF·중심 유사도는 다른 양입니다.
- 소속도가 낮거나 1·2순위 차이가 작으면 `needs_review`를 표시합니다. 대표 응답만으로 소수 의견이나 반례를 알 수 없으므로 UI의 응답별 조회를 함께 사용합니다.

## 10. 감정사전·형태소 규칙과 근거

프로젝트가 직접 작성한 `data/sentiment_ko.tsv` 160항목을 배포합니다. 항목은 표제어·극성 가중치·검토 우선 가중치·종류·별칭을 가집니다. 사전 버전과 SHA-256을 분석 기록에 저장합니다. 외부 KNU 사전 또는 학습된 감정 분류기로 표시하지 않습니다.

1. 전체 형태소열에서 가장 긴 사전 표현을 먼저 매칭합니다. 활용형과 `하다`형을 처리하고 `불만족` 안의 `만족`처럼 중첩한 긍정을 이중 계산하지 않습니다.
2. 같은 절의 가까운 `안`, `못`, `않다`, `아니다`, `없다`와 부정 상태의 `해결`·`해소`를 처리합니다. 부정 한 번마다 가중치를 `-0.75`배 하므로 이중 부정도 계산합니다. 절 경계를 넘어 다른 평가에 부정을 적용하지 않습니다.
3. 강조 부사에는 1.25배, 약화에는 0.65배를 적용하고 표현별 가중치는 -1~1로 제한합니다. 감지한 조건·가정 표현은 극성을 0으로 두고 검토 필요로 표시합니다. `만족도 조사`, `불편 사항 확인` 같은 조사 대상의 언급은 감정으로 세지 않습니다.
4. `개선`, `필요`, `요청`은 그 자체로 부정 감정이 아닙니다. 별도 요청 종류와 검토 우선 가중치를 사용합니다.

규칙 버전 `1.1.0`은 사전 버전 `1.0.0`과 구분해 기록합니다. `부족한 점이 없다`의 간접 부정, `도움이 안 된다`의 후행 부정, `해결이 필요하다`와 해결 완료의 구분, `업무 지침`·`안전 교육` 같은 중립 명사 문맥을 보완합니다. 가정·희망 상태는 관찰된 감정으로 확정하지 않습니다. `review_reasons`는 인용, 간접화법, 의문·판단 유보, 반어 가능성, 가정, 희망·요청 상태, 사전 근거 없음, 대체 형태소 분석을 구분합니다. 이 표시가 모든 반어나 다의어를 포착한다는 뜻은 아닙니다.

```text
polarity_score = tanh((positive_sum - negative_sum) / 1.5)
priority_to_review = 1 - product(1 - matched_urgency_weight)
```

긍정·부정 가중치가 각각 0.15 이상이면 `mixed`, 그 외 극성이 0.10 이상이면 `positive`, -0.10 이하이면 `negative`, 나머지는 `neutral`입니다. 이 기준은 정답 코퍼스로 보정된 확률 임계치가 아닙니다.

각 응답은 매칭 표제어, 정규화된 마스킹 문장 기준 문자 구간, 적용한 부정·강조 규칙과 가중치를 보존합니다. `evidence_status`는 `matched`(극성 근거), `request_only`(요청·긴급·가정 등 극성 없는 매칭), `no_match`(매칭 없음)입니다. 중립이 실제 무감정 또는 만족을 입증하지 않습니다.

토픽별로 모든 원래 응답의 긍정·중립·부정·혼합 건수, 극성·우선도 평균, 극성 근거 포함률을 계산합니다. 토픽 주 감정은 최빈값이며 동률에는 혼합·평균 방향·중립 순의 명시된 규칙을 적용합니다. 토픽 병합 후에도 같은 응답별 분석으로 다시 집계합니다.

외부 AI의 대표 의견 해석은 토픽의 설명·감정 요약을 보강할 수 있습니다. 응답별 사전 감정 분포는 바꾸지 않으며 `sentiment_distribution_method=document_lexicon`으로 출처를 구분합니다. 외부 응답은 근거 존재 여부와 값 범위를 확인하고 실패 시 로컬 결과를 유지합니다.

감정 신호는 반어·인용·다의어·간접 표현을 완전히 해석하지 못합니다. 자체 32개 회귀 사례의 통과율은 개발 검증일 뿐 외부 정확도가 아닙니다. 일반화 성능을 주장하려면 독립 한국어 설문에 복수 평가자 라벨을 붙이고 별도 표본에서 클래스별 precision·recall·F1, macro-F1, 혼동행렬, 근거 coverage를 측정해야 합니다. 감정이나 검토 우선도는 개인의 심리 상태·실제 위험도 판단값이 아닙니다.

## 11. 그룹 비교

선택된 범주형 컬럼별로 토픽 빈도와 그룹 내 비율을 계산합니다. 한 셀의 응답 수가 5건 미만이면 `count`, `display_count`, `share`, 감정별 건수를 모두 숨깁니다. 이상치와 존재하지 않는 토픽 배정은 제외합니다. 기존 저장본의 억제 셀도 보고서에서 다시 숨깁니다. 이 억제는 단순 노출 완화 장치일 뿐 재식별 위험을 정량적으로 보장하는 익명성 기법은 아닙니다. 작은 그룹, 희귀 속성, 외부 정보와의 결합 가능성을 사람이 검토해야 합니다.

토픽 병합·제외 후에는 소속도와 현재 분포를 갱신하고 이전 점수는 `original_model_diagnostics`에 보존합니다. `diagnostics_status=invalidated_by_user_edit`는 편집 후 재적합·품질 재평가가 없었다는 뜻입니다. UI에서는 현재 품질 점수를 미평가로 표시하고 보고서는 점수의 편집 전 범위를 명시합니다. 전체 감정 요약은 토픽에서 제외한 응답도 포함하는 원래 분석 집합 기준입니다.

## 12. 알려진 한계와 전문가 검토 질문

- 짧은 자유응답에서는 단어 동시출현이 희박해 LDA와 coherence가 불안정할 수 있습니다.
- class-based TF-IDF와 단어·구 중복 억제는 키워드 해석을 돕는 표현 단계일 뿐 토픽의 의미적 정답성을 검증하지 않습니다.
- Kiwi 명사 중심 처리로 서술어, 부정 범위, 문맥, 신조어 일부가 손실될 수 있습니다.
- 후보 분리도는 공통 공간에서 비교하지만 사용한 임베딩·전처리 자체의 편향을 제거하지 않습니다. 다른 조사 사이의 절대 품질 점수로 비교하지 마세요.
- 500회 bootstrap은 선택된 배정을 고정한 조건부 진단이고, 5회 80% 층화 부분표본만 모델을 다시 적합합니다. 시간 순서·기관 간 이동·신규 표본 재현성을 평가하지 않습니다.
- 가중치 시나리오는 기본 가중치의 50–150% 범위만 탐색합니다. 복합 가중치, 변동 범위와 70% 관문은 공개 정답 데이터나 전문가 선호 자료로 보정되지 않았습니다.
- 분리도·해석 가능성·다양성 등 지표 사이의 상관과 이중 계산 가능성을 별도 통계 모형으로 보정하지 않습니다.
- 명시적 가설·효과크기·정답셋이 없어 고전적 통계적 검정력, p-value 또는 정확도를 제공하지 않습니다.
- 자동 라벨은 키워드·대표 응답에 근거한 작업용 명칭입니다. 담당자가 이름을 수정하고 `record_review`로 승인자를 기록할 수 있으며 승인 후 구조를 바꾸면 상태가 `changes_pending_review`로 돌아갑니다.
- 외부 AI 해석은 provider 모델과 정책에 따라 달라지며 사실성이나 공정성을 보장하지 않습니다.
- 표본이 작을수록 결과를 “토픽모델링 성능”보다 탐색적 테마 코딩 보조로 해석해야 합니다.

권장 검토 순서는 `(1) 제외·마스킹 응답 확인 → (2) 후보별 대표 응답 비교 → (3) 토픽 라벨 수정 → (4) 작은 그룹 보호 확인 → (5) 조치 가능성 검토`입니다.
