# 분석 방법론

이 문서는 AI Survey Insight 0.1.0의 **현재 코드가 실제로 수행하는 계산**을 설명합니다. 이 도구의 결과는 탐색적 HR 분석을 돕는 후보안이며, 정답 라벨·통계적 유의성·심리 상태·개인의 위험도를 판정하지 않습니다. 내부 JSON 필드는 하위 호환성을 위해 유지될 수 있으므로, 사용자 표시 명칭과 내부 필드명이 다른 경우 아래 대응표를 기준으로 해석합니다.

## 1. 처리 단위와 재현성

- 입력은 CSV 또는 XLSX의 행이며, 사용자가 선택하거나 자동 추천된 한 컬럼을 자유응답으로 분석합니다.
- 로컬 후보 모델의 기본 난수 시드는 `42`입니다. CLI의 `--seed` 또는 API 요청의 `seed`로 바꿀 수 있습니다.
- 같은 라이브러리 버전·운영체제·입력·전처리·시드를 사용하면 로컬 후보 선택과 핵심 결과가 재현되도록 구성합니다. 라이브러리 버전, 부동소수점 구현 또는 외부 provider 응답이 달라지면 결과도 달라질 수 있습니다.
- 생성되는 `candidate_id`, `run_id`, `document_id`는 실행마다 새로 만들어지므로 재현성 비교 대상이 아닙니다.

## 2. 자유응답 컬럼 탐지

각 컬럼에 대해 헤더 의미, 문자열 길이, 자연어 형태, 고유값 비율, 문장형 표현을 계산합니다.

```text
text_score =
  0.25 × header_semantic
  + 0.25 × length_signal
  + 0.20 × value_type_signal
  + 0.15 × cardinality_signal
  + 0.10 × sentence_signal
  + 0.05 × model_vote
```

결측률이 95%를 넘으면 점수에 `0.65`를 곱합니다. `text_score >= 0.50`인 컬럼을 후보로 제시하고, `0.70` 이상은 `Free-text Response`, `0.50–0.70`은 `Free-text Candidate`로 표시합니다. 이는 지도학습 정확도가 검증된 분류기가 아니라 규칙 기반 프로파일러입니다. 헤더나 응답 형식이 특이한 데이터에서는 사용자가 컬럼을 직접 확인해야 합니다.

## 3. 전처리와 개인정보 패턴 마스킹

1. 줄바꿈과 공백을 정규화합니다.
2. 빈 문자열, `.`, `-`, `없음`, `해당 없음`, `의견 없음`, `N/A` 등 코드에 정의된 값을 무응답으로 제외합니다.
3. 이메일, 국내 이동전화 번호, `사번`·`직번`·`employee id` 뒤의 식별자 패턴을 각각 `[EMAIL]`, `[PHONE]`, `[EMPLOYEE_ID]`로 치환합니다.
4. `성명:`, `주소:`, 주민등록번호·계좌번호 같은 명시적 고위험 문맥은 광범위하게 자동 삭제하지 않고 `privacy_review_flags`로 표시해 사람이 확인하게 합니다.
5. Kiwi를 사용할 수 있으면 명사 태그를 추출하고, 불가능하면 KoNLPy Okt, 그마저 불가능하면 한글·영문·숫자 정규식 토큰으로 순차 대체합니다.
6. 1글자 토큰, 숫자 전용 토큰, 코드에 정의된 불용어를 제거하고 1–2그램을 만듭니다.

이 마스킹은 제한된 정규식 필터이며 이름, 주소, 희귀 직무명, 서술형 간접 식별자 등을 완전하게 탐지하거나 익명화하지 않습니다. 분석·보고서 배포 전 담당자의 재검토가 필요합니다.

## 4. 표현 공간

모델의 통계적 가정에 맞춰 입력 공간을 분리합니다.

| 용도 | 표현 | 현재 설정 |
|---|---|---|
| KMeans·계층 군집·NMF | TF-IDF | 명사/대체 토큰, 1–2그램, `min_df=1`, `max_df=0.95` |
| LDA | 정수 단어 빈도 | 같은 어휘 규칙의 `CountVectorizer`; TF-IDF를 LDA에 넣지 않음 |
| 로컬 DBSCAN | TF-IDF → Truncated SVD → 정규화 | 최대 10개 SVD 성분, cosine 거리 |
| 선택적 의미 군집 | provider embedding | KMeans·계층 군집·DBSCAN 후보에 사용 |

어휘 행렬을 만들 수 없는 극단적으로 짧은 텍스트에서는 문자 2–4그램으로 대체합니다. 문자 대체가 발생하면 형태소 기반 결과와 해석 방식이 다르므로 토크나이저 기록을 확인해야 합니다.

## 5. 토픽 후보 모델

유효 응답 수에 따라 허용 토픽 수와 최소 토픽 크기를 먼저 제한한 뒤 후보를 만듭니다.

| 유효 응답 수 | 모드 | 허용 토픽 수 | 최소 토픽 크기 |
|---:|---|---:|---:|
| 0–14 | 초소표본 모드 | 1–3 | 2 |
| 15–29 | 소표본 모드 | 2–4 | 2 |
| 30–49 | 소형 설문 모드 | 3–6 | `max(3, ceil(0.08N))` |
| 50–199 | 표준 모드 | 4–10 | `max(4, ceil(0.04N))` |
| 200–999 | 대형 설문 모드 | 6–20 | `max(5, ceil(0.02N))` |
| 1,000 이상 | 대량 분석 모드 | 10–30 | `max(10, ceil(0.01N))` |

- **KMeans**: TF-IDF 또는 선택적 embedding에서 고정 `k` 후보를 생성합니다. 수렴 경고가 발생하거나 요청한 수보다 실제 군집 수가 적게 만들어진 붕괴 후보는 버립니다.
- **계층 군집**: 평균 연결과 cosine 거리를 사용합니다. TF-IDF와 embedding 모두 응답 250건 이하에서만 실행해 밀집 행렬 메모리 사용을 제한합니다.
- **NMF**: TF-IDF의 비음수 행렬을 분해합니다. 문서–토픽 가중치의 최댓값으로 주 토픽을 정하고, **NMF 성분 자체**에서 상위 단어를 뽑습니다. 최대 반복 횟수 안에 수렴하지 않은 후보는 경쟁표에서 제외합니다.
- **LDA**: 정수 단어 빈도 행렬을 batch 방식으로 적합합니다. 문서별 사후 토픽 분포의 최댓값으로 주 토픽을 정하고, **LDA 토픽–단어 성분 자체**에서 상위 단어를 뽑습니다. LDA는 [Blei, Ng, Jordan (2003)](https://www.jmlr.org/papers/v3/blei03a.html)의 생성 확률 모델 계열이지만, 이 제품은 짧은 설문 응답에 맞춘 탐색 도구이지 논문의 가정을 검증하는 도구는 아닙니다.
- **DBSCAN**: 정해진 `k` 대신 밀도에서 자연 군집 수를 얻습니다. 로컬 TF-IDF 후보는 `eps=0.35–0.75`, embedding 후보는 `eps=0.15–0.35`의 제한된 격자를 비교합니다. `-1`은 노이즈 응답으로 남깁니다.
- **선택적 embedding**: 사용자가 provider와 키를 제공한 경우에만 의미 벡터 후보를 추가합니다. provider 호출이 실패하거나 Claude처럼 별도 embedding 경로가 없는 설정이면 로컬 후보만 사용합니다.

scikit-learn도 토픽 추출 예제에서 [NMF에는 TF-IDF, LDA에는 단어 빈도](https://scikit-learn.org/stable/auto_examples/applications/plot_topics_extraction_with_nmf_lda.html)를 사용합니다. 본 구현은 이 입력 구분을 따릅니다.

## 6. 구조 관문

후보 점수를 비교하기 전에 다음 조건을 별도 관문으로 검사합니다.

1. 유효 토픽이 한 개 이상이어야 합니다.
2. 각 토픽은 해당 표본 모드의 최소 토픽 크기 이상이어야 합니다.
3. DBSCAN처럼 노이즈를 허용하는 후보도 전체 유효 응답의 70% 이상을 토픽에 포함해야 합니다.
4. 고정 `k` 모델은 실제로 `k`개 군집이 생성되어야 합니다.
5. LDA는 절반 이상의 응답이 서로 다른 유효 단어 3개 미만이면 입력 근거 부족으로 관문을 통과하지 못합니다.

하나 이상의 후보가 관문을 통과하면 통과 후보만 권장안 경쟁에 참여합니다. 모두 실패하면 차선 후보를 표시하고 경고를 남깁니다. 70%는 보편적 통계 기준이 아니라 과도한 제외를 막기 위한 제품 정책값입니다.

## 7. 평가 지표와 실제 계산 의미

모든 값은 같은 입력 코퍼스 안의 후보를 정렬하기 위한 휴리스틱입니다. 서로 다른 조사·언어·전처리 결과 사이의 절대 품질 또는 정확도로 비교하면 안 됩니다.

| 사용자 표시 명칭 | 내부 필드 | 현재 계산 |
|---|---|---|
| 군집 품질 종합점수 | `stability` | 분리도 0.40 + 해석 가능성 0.30 + 균형 0.20 + 0.10 − 소형 토픽 비율×0.20. 과거 필드명을 유지한 복합 휴리스틱이며 통계적 안정성 검정이 아님 |
| 토픽 해석 가능성 점수 | `coherence` | 상위 5개 키워드의 문서 동시출현으로 계산한 bounded UMass-style 값 |
| 군집 분리도 | `semantic_quality` | 노이즈를 제외한 cosine silhouette. 음수는 0으로 제한 |
| 분석 포함률 | `coverage` | `-1` 노이즈가 아닌 응답 수 / 유효 응답 수 |
| 토픽 키워드 다양성 | `diversity` | 토픽별 상위 5개 키워드 중 고유 키워드 비율 |
| 라벨 해석 가능성 | `labelability` | 토픽당 최대 5개 키워드(60%)와 최대 3개 대표 응답(40%)의 존재량 |
| 토픽 크기 균형 | `balance` | 토픽 크기의 정규화 엔트로피에서 65% 초과 최대 점유율을 감점 |
| 부분표본 일치도 | `resampling_stability` | 선정 후보에 한해 토픽별 80% 층화 부분표본을 3회 다시 적합하고 원 분할과의 Adjusted Rand Index를 평균한 사후 진단값. 권장 점수에는 미포함 |

토픽 해석 가능성 점수는 각 토픽의 순서 있는 키워드 쌍에 대해 아래 값을 평균하고 지수화해 0–1로 제한합니다.

```text
raw_pair = log(min(1, (D(w_i, w_j) + 1) / max(1, D(w_j))))
coherence = exp(mean(raw_pair))
```

이는 [Röder et al. (2015)](https://doi.org/10.1145/2684822.2685324)이 정리한 coherence 계열을 참고한 **제품용 bounded UMass-style 변형**입니다. 논문의 모든 구성·외부 참조 코퍼스·사람 평가를 재현한 구현은 아닙니다. 군집 분리도는 [silhouette 계열](https://doi.org/10.1016/0377-0427(87)90125-7)을 사용하지만, 고차원 희소 텍스트에서 높은 값이 곧 의미적으로 좋은 토픽을 보장하지 않습니다.

## 8. 권장 토픽 수 판정

관문을 통과한 후보의 복합 평가값은 다음과 같습니다.

```text
score =
  0.30 × 군집 분리도
  + 0.25 × 토픽 해석 가능성 점수
  + 0.15 × 분석 포함률
  + 0.10 × 토픽 키워드 다양성
  + 0.10 × 라벨 해석 가능성
  + 0.10 × 토픽 크기 균형
  − penalty
```

`penalty`는 최소 크기 미달 토픽 비율, 응답 수 대비 과도한 파편화, 75%를 넘는 단일 토픽 점유, 노이즈 비율, 중복 키워드를 결합하며 최대 `0.35`입니다. 최고점과 `max(0.03, 최고점의 5%)` 이내인 후보가 여러 개면 더 단순한 작은 토픽 수를 권장합니다. 더 넓은 대안과 더 세분화한 대안도 별도로 제공합니다.

이 가중치와 임계값은 공개 benchmark로 최적화된 값이 아니라 설명 가능성과 운영상 검토 가능성을 위한 제품 정책입니다. 따라서 화면과 보고서에서는 “최적 토픽 수”가 아니라 **권장 토픽 수**라고 표시합니다.

권장 후보가 정해진 뒤에는 각 토픽에서 80%를 층화 추출한 부분표본을 고정 seed로 3회 다시 적합합니다. 원래 분할과 부분표본 분할은 라벨 번호 순열에 영향을 받지 않는 [Adjusted Rand Index](https://doi.org/10.1007/BF01908075)로 비교합니다. 평균이 0.60 미만이면 경고하지만 권장 점수를 사후 변경하지 않습니다. 이는 작은 표본 변화에 대한 민감도 진단이며, 완전한 bootstrap 신뢰구간·시간 안정성·외부 재현성을 증명하지 않습니다. DBSCAN 권장 후보는 현재 이 진단을 지원하지 않아 별도 경고합니다.

## 9. 대표 의견과 배정 확률

- KMeans·계층 군집·DBSCAN 후보는 해당 군집의 평균 벡터와 cosine 유사도가 높은 중복 없는 응답을 최대 3개 선택합니다. 이 모델들의 `probability=1.0`은 확률 추정치가 아니라 하드 배정 표시입니다.
- NMF·LDA 후보는 배정된 토픽에 대한 문서–토픽 가중치가 큰 응답을 최대 3개 선택합니다. 배정값은 행별 토픽 가중치를 합이 1이 되도록 정규화해 저장합니다.
- 대표 의견은 전형적인 예를 보여주지만 소수 의견, 반례 또는 가장 중요한 의견을 보장하지 않습니다. 원자료와 다른 응답도 함께 읽어야 합니다.

## 10. 감정 신호와 처리 우선도

기본 모드는 한국어 어휘와 부정 표현 규칙으로 긍정·중립·부정·혼합 신호와 처리 우선도 보조값을 계산합니다. 학습 모델이 아니며, 코드에 명시된 어휘를 실행마다 같은 방식으로 계산합니다.

1. 긍정 어휘(`만족`, `도움`, `체계적`, `명확`, `효율` 등)와 부정·개선 요구 어휘(`불만`, `부족`, `복잡`, `불편`, `필요`, `개선` 등)의 가중치를 합산합니다. 같은 canonical 어휘는 한 응답에서 최초 유효 출현 한 번만 셉니다.
2. 긍정 표현 뒤의 `않`, `못`, `아니`, `없`과 부정 표현 뒤의 `없`, `않`, `아니`, `해소`, `해결`을 짧은 범위에서 찾아 단순 부정을 억제합니다. `불만족` 안의 `만족`도 긍정으로 중복 계산하지 않습니다.
3. 응답별 극성 점수는 아래와 같이 `-1–1` 범위로 제한합니다.

```text
polarity = (positive_sum - negative_sum) / max(1, positive_sum + negative_sum)
```

긍정·부정 근거가 모두 있으면 `mixed`, 그렇지 않고 점수가 `0.15` 이상이면 `positive`, `-0.15` 이하면 `negative`, 나머지는 `neutral`입니다. 이 임계값은 아직 한국어 HR 정답 코퍼스로 보정된 값이 아닙니다.

4. `즉시`, `당장`, `긴급`, `시급`, `조속` 같은 명시적 우선 표현과 일부 불만·개선 어휘의 작은 우선 가중치를 아래처럼 결합합니다.

```text
priority_to_review = 1 - product(1 - matched_weight)
```

5. 토픽 단위 극성·우선 값은 배정된 모든 응답 점수의 산술평균입니다. 토픽 라벨은 응답 라벨 최빈값을 사용하고, 동률이면 `mixed`, 평균 극성 방향, `neutral` 순서의 명시적 규칙으로 정합니다. 화면의 토픽 정렬값은 `0.55 × 처리 우선도 + 0.45 × 토픽 비율`이며 모델 결과에 저장되는 새로운 감정 확률은 아닙니다.

선택 모드는 사용자가 제공한 AI provider로 마스킹된 대표 텍스트·키워드·로컬 근거에 기반한 해석을 보강할 수 있습니다. 외부 응답의 라벨·점수 범위가 유효하고 제시 근거가 기존 키워드·대표 응답·로컬 근거에 실제로 존재할 때만 로컬 감정 필드를 교체합니다. provider 실패, 범위 이탈, 무근거 응답이면 로컬 신호를 유지합니다.

감정 결과는 심리 진단·임상 판단·직원 개인 평가가 아닙니다. 처리 우선도는 긴급성 또는 실제 위험도를 판정하지 않으며, 담당자가 먼저 읽을 필요가 있는 표현을 정렬하는 보조지표입니다.

어휘·규칙 기반 감정분석은 [VADER 연구](https://ojs.aaai.org/index.php/ICWSM/article/view/14550)처럼 학계에서 사용되는 접근 계열입니다. 다만 VADER는 사람이 평정한 어휘사전과 독립 코퍼스 평가를 포함합니다. 이 프로젝트의 작은 한국어 HR 어휘사전은 그런 검증을 아직 거치지 않았으므로 **검증된 감정분류기**가 아니라 감사 가능한 baseline으로만 설명합니다. 단일 lexicon이 다른 결론을 낼 수 있다는 [비교 연구](https://doi.org/10.1371/journal.pone.0275910)도 알려져 있습니다.

학술적 타당성을 주장하려면 실제 배포 목적과 같은 한국어 HR 응답을 개인정보 제거 후 표집하고, 최소 두 명의 독립 평가자가 명시적 지침으로 라벨링한 뒤 합의도, class별 precision·recall·F1, macro-F1, 혼동행렬, 무근거 응답 coverage를 별도 hold-out 표본에서 보고해야 합니다. 해당 평가 전에는 정확도 수치를 제시하지 않습니다.

## 11. 그룹 비교

선택된 범주형 컬럼별로 토픽 빈도와 그룹 내 비율을 계산합니다. 한 셀의 응답 수가 5건 미만이면 `display_count`를 숨깁니다. 이 억제는 단순 노출 완화 장치일 뿐 재식별 위험을 정량적으로 보장하는 익명성 기법은 아닙니다. 작은 그룹, 희귀 속성, 외부 정보와의 결합 가능성을 사람이 검토해야 합니다.

## 12. 알려진 한계와 전문가 검토 질문

- 짧은 자유응답에서는 단어 동시출현이 희박해 LDA와 coherence가 불안정할 수 있습니다.
- Kiwi 명사 중심 처리로 서술어, 부정 범위, 문맥, 신조어 일부가 손실될 수 있습니다.
- 서로 다른 표현 공간의 silhouette 값은 완전히 동등한 척도가 아닙니다. embedding 후보와 TF-IDF 후보의 점수 차이는 대표 응답과 함께 판단해야 합니다.
- 선정 후보의 3회 80% 층화 부분표본 일치도는 계산하지만, 반복 수가 적고 시간 순서도 사용하지 않으므로 완전한 bootstrap 신뢰구간이나 시간 분할 안정성은 아닙니다.
- 복합 가중치와 70% 관문은 공개 정답 데이터로 보정되지 않았습니다.
- 자동 라벨은 키워드·대표 응답에 근거한 작업용 명칭입니다. 담당자가 이름을 수정하고 `record_review`로 승인자를 기록할 수 있으며 승인 후 구조를 바꾸면 상태가 `changes_pending_review`로 돌아갑니다.
- 외부 AI 해석은 provider 모델과 정책에 따라 달라지며 사실성이나 공정성을 보장하지 않습니다.
- 표본이 작을수록 결과를 “토픽모델링 성능”보다 탐색적 테마 코딩 보조로 해석해야 합니다.

권장 검토 순서는 `(1) 제외·마스킹 응답 확인 → (2) 후보별 대표 응답 비교 → (3) 토픽 라벨 수정 → (4) 작은 그룹 보호 확인 → (5) 조치 가능성 검토`입니다.
